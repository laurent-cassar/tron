main.cpp → WinMain() / WndProc()

Fenêtre & boucle de jeu

WndProc

Callback appelé automatiquement par Windows à chaque événement sur la fenêtre (clic, redimensionnement, fermeture...). C'est Windows qui décide quand l'appeler — on ne fait qu'y réagir. On ne traite ici que WM_DESTROY, pour fermer proprement l'application ; tout le reste passe par le comportement par défaut (DefWindowProc).

WinMain

  • Enregistre la classe de fenêtre
  • Crée et affiche la fenêtre
  • Initialise le Renderer (Init)
  • Boucle : messages Windows, sinon Render()
Pourquoi PeekMessage et pas GetMessage ? GetMessage attend qu'un message arrive avant de rendre la main — bloquant, donc inutilisable pour un jeu. PeekMessage revient immédiatement, message ou pas : c'est ce qui permet d'appeler Render() en boucle, des centaines de fois par seconde.
main.cpp
while (msg.message != WM_QUIT)
{
  if (PeekMessage(&msg, ...))
  {
    TranslateMessage(&msg);
    DispatchMessage(&msg);
  }
  else
  {
    g_renderer.Render();
  }
}
Renderer.cpp → InitD3D()

Device, Swap Chain, Depth Buffer

DeviceCrée les ressources GPU (buffers, textures, shaders) — la « fabrique », presque jamais utilisée après l'initialisation
Device ContextEnvoie les commandes de dessin au GPU à chaque frame — c'est lui qu'on utilise dans Render()
Swap Chain2 images en mémoire : une affichée, une en cours de dessin — Present() les échange
Depth BufferMémorise la profondeur de chaque pixel — indispensable dès que des objets se chevauchent
Device crée, Context dessine — une séparation qu'on retrouve dans la plupart des API modernes (D3D12, Vulkan, Metal).
Le choix Direct3D 11 se fait ici :
InitD3D()
D3D_FEATURE_LEVEL
  featureLevel =
  D3D_FEATURE_LEVEL_11_0;

Pourquoi 11, pas 12 ?

D3D11 : le driver gère la synchro GPU et les ressources.
D3D12 : c'est vous qui gérez tout — plus rapide, mais bien plus de code.

Renderer.cpp → InitPipeline()

Shaders & Input Layout

Vertex Shader

  • Tourne une fois par sommet
  • Transforme la position 3D en position écran
  • Utilise la matrice WVP

Pixel Shader

  • Tourne une fois par pixel
  • Calcule la couleur finale
  • Ici : renvoie simplement la couleur du sommet
Input Layout — doit correspondre à la struct du Vertex Shader
POSITION   float3, offset 0        COLOR   float3, offset 12
Les mots en majuscules (POSITION, COLOR, SV_POSITION) sont des semantics HLSL : des étiquettes qui disent au GPU à quoi correspond chaque donnée et où elle va dans le pipeline. SV_POSITION est obligatoire en sortie du Vertex Shader — c'est la position finale à l'écran.
Renderer.cpp → InitMesh()

Mesh procédural

8 sommets, 12 triangles
  • 8 sommets = les coins du cube, chacun avec une position et une couleur
  • 36 indices (12 triangles) décrivent comment relier les sommets
  • « Procédural » : généré par du code, pas chargé depuis un fichier .obj
  • Sans indices, il faudrait dupliquer chaque sommet partagé (36 sommets au lieu de 8) — les indices économisent la mémoire et permettent au GPU de réutiliser un sommet déjà calculé
  • L'ordre des indices (0,3,2 puis 0,2,1 pour la première face...) n'est pas arbitraire : c'est lui qui rend CullMode = Back correct (slide suivante)
  • Même principe pour générer vaisseaux et astéroïdes plus tard

Rasterizer & boucle de rendu

CullMode = Back Ignore les faces qui nous tournent le dos
FillMode = Solid Remplit les triangles (pas juste leurs contours)
Viewport Définit la zone d'écran où dessiner

La boucle Render(), à chaque frame :

Clear
→
Update
→
Draw
→
Present
Clear efface l'image précédente (sinon l'ancienne frame resterait visible) · Update renvoie la matrice WVP au GPU via le constant buffer · Draw déclenche le pipeline (vertex → pixel → rasterizer) · Present(1,0) échange les deux images de la Swap Chain — le « 1 » active la V-Sync, pour éviter le tearing.

Pourquoi Direct3D 11 ?

Direct3D 11 ✓Direct3D 12
Synchro GPUAutomatique (driver)Manuelle (fences)
Ressources shaderUn appel (SetShaderResources)Descriptor heaps à gérer
Mise en œuvreRapide à apprendreBas niveau, complexe
Pour 2 semaines, avec une équipe qui découvre Direct3D : D3D11 reste largement suffisant, et bien plus sûr. D3D12 ne devient intéressant que pour soumettre des milliers d'appels de dessin par frame en tirant parti de plusieurs cœurs CPU — un problème que vous n'aurez pas avec un mesh procédural et quelques ennemis.

Animation 3D vs Stéréoscopie

Animation 3D

  • Simule la profondeur sur un écran plat
  • Perspective, ombres, mouvement
  • Une seule image, pour les deux yeux

Stéréoscopie

  • Une image différente pour chaque œil
  • Reproduit la vision binoculaire humaine
  • Nécessite un dispositif (lunettes, casque VR)

Étymologie

στερεός (stereós) — solide, en volume
σκοπεῖν (skopein) — regarder, observer
→ stéréoscopie = littéralement « voir en volume »
